# FastAPI Model Inference & Embeddings API

An **asynchronous** FastAPI service that serves real-time machine-learning
predictions and text embeddings with a **sub-200ms latency target**.

- `POST /predict` — sentiment classification of a review
  (`positive` / `negative` / `neutral`) with confidence and all class scores.
- `POST /embed` — dense 512-dim TF-IDF text embeddings (batch up to 100),
  ready for cosine similarity / retrieval use.
- `GET /health`, `GET /metadata` — liveness and model-card endpoints.

Built for the InternFlow AI Engineer internship (supervisor-assigned task:
*"Deploy asynchronous FastAPI endpoint serving real-time model predictions
with sub-200ms latency"*).

## Model

- **Classifier:** TF-IDF (word 1–2 grams + char_wb 3–5 grams) → tuned
  Logistic Regression (`C=5.0`, 5-fold CV on `f1_macro`).
- **Embedder:** standalone TF-IDF (word 1–2 grams, `max_features=512`,
  sublinear TF, L2 norm), fitted on the cleaned training texts.
- **Dataset:** `data/reviews.csv` — 450 short product reviews, 150 per
  class, generated reproducibly with a seeded script from 90 hand-written
  seeds (see `data/DATASET.md`).
- **Held-out test (90 reviews):** accuracy **1.0000**, macro F1 **1.0000**
  (MultinomialNB baseline: 0.9556 / 0.9554).

## Why it is async

Every inference handler is `async def`. scikit-learn is synchronous, so
prediction/embedding calls run in a bounded `ThreadPoolExecutor` via
`loop.run_in_executor(...)` — the event loop never blocks, and concurrent
requests are served in parallel instead of serially. Each response carries
the server-side inference time (`latency_ms`).

## Quickstart

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 1. (re)generate the dataset — deterministic, seed 42
python scripts/make_dataset.py

# 2. train the classifier + embedder -> models/
python src/train.py

# 3. run the API
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Interactive docs: http://localhost:8000/docs

## API examples

```bash
# health
curl http://localhost:8000/health

# predict
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"text": "The product works perfectly, very happy"}'
# {"text": "...", "sentiment": "positive", "confidence": 0.835,
#  "all_scores": {"negative": 0.0589, "neutral": 0.1062, "positive": 0.835},
#  "latency_ms": 11.59}

# embeddings (batch)
curl -X POST http://localhost:8000/embed \
  -H "Content-Type: application/json" \
  -d '{"texts": ["great product", "terrible quality"]}'
# {"embeddings": [[...512 floats...], [...]], "dim": 512, "count": 2,
#  "latency_ms": 1.379}

# model card
curl http://localhost:8000/metadata
```

`demo/sample_predictions.md` contains 12 live predictions and embedding
similarity examples generated by `python demo.py`.

## Latency benchmark

`python scripts/benchmark.py` — 200 sequential requests per endpoint plus a
50-way concurrent burst (results in `benchmark/results.json`).

| Scenario | p50 | p95 | mean | max |
|---|---|---|---|---|
| `POST /predict` (sequential) | 4.63 ms | 14.09 ms | 6.40 ms | 25.92 ms |
| `POST /embed` (sequential) | 3.34 ms | 10.85 ms | 4.89 ms | 112.81 ms |
| `POST /predict` (50 concurrent) | 126.26 ms | 220.10 ms | 122.45 ms | 226.52 ms |

Real-time single-request serving is far under the 200 ms target on both
endpoints. The 50-way burst was measured in-process on shared CI hardware,
where wall-clock includes GIL contention and thread-pool queueing; the event
loop itself stays responsive and all 50 requests complete correctly. In a
real deployment, run uvicorn with multiple workers
(`uvicorn app.main:app --workers 4`) to scale concurrent throughput.

## Limitations

1. **Synthetic training data.** Reviews were written/augmented by the author,
   not scraped from a real marketplace; phrasing outside the seed vocabulary
   can be misclassified (see `demo/sample_predictions.md` row 1 — a genuinely
   positive review the model scores as negative with 0.68 confidence).
2. **Lexical embeddings.** TF-IDF vectors capture word overlap, not true
   semantics — "great product" and "terrible product" are far apart only
   because the words differ.
3. **English only.** The cleaning pipeline lowercases and strips non-word
   characters; other languages are untested.
4. **Single model version.** No A/B, canary, or hot-reload; redeploy to
   update the model.
5. **CPU-bound inference under GIL.** Throughput scales with uvicorn workers,
   not threads, for heavy concurrent load.

## Future improvements

1. Swap the TF-IDF embedder for a compact sentence-transformer
   (e.g. MiniLM) served via ONNX for true semantic embeddings at similar
   latency.
2. Add request logging + Prometheus latency histograms and autoscaling on
   p95, so the 200 ms target is enforced in production, not just measured.
